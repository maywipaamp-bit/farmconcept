# Standard — ระบบ The Farm Concept

ไฟล์นี้คือกฎที่ต้องทำตามทุกครั้งที่สร้างหรือแก้ UI ในโปรเจกต์นี้

## หลักการ
ปัญหาเดิมของระบบคือ "เข้มและหนักเกินไป" — ข้อความเกือบทุกจุดใช้ตัวหนาและสีเกือบดำ
ความสำคัญของข้อความสื่อด้วย **สี** ก่อน แล้วจึงเป็น **น้ำหนัก** และ **ขนาด** ตามลำดับ

## กฎที่ห้ามฝ่าฝืน
1. `font-weight: 400` เป็นค่าเริ่มต้น · ใช้ `500` เฉพาะที่ต้องเน้น · `600` เฉพาะหัวข้อ · **ห้ามใช้ 700**
2. ห้ามใช้ `#000` หรือสีดำสนิทกับข้อความ — เข้มสุดคือ `var(--text-strong)` = #111827
3. line-height ของเนื้อหาไทยไม่ต่ำกว่า **1.6** (หัวข้อ 1.35–1.5)
4. ขนาดตัวอักษรเล็กสุด **12px** และใช้เฉพาะ badge / caption
5. หัวตารางเป็น 13px / 500 / `--text-secondary` — ไม่ใช่ตัวหนา ไม่ใช่สีเข้ม
6. หนึ่งหน้าจอมีปุ่ม `.btn--primary` (เขียว) ได้ **หนึ่งปุ่ม** เท่านั้น
7. ห้าม hardcode สี ขนาด หรือระยะห่าง — ใช้ตัวแปรใน `tokens.css` เท่านั้น
8. ระยะห่างใช้เฉพาะสเกล 4px: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64
9. ตัวเลข วันที่ และคอลัมน์จำนวน ต้องมี `font-variant-numeric: tabular-nums`
10. ห้ามใส่ตัวพิมพ์ใหญ่ทั้งคำ (`text-transform: uppercase`) กับข้อความไทย

## โครงสร้างหน้าจอมาตรฐาน
- Sidebar 244px พื้นขาว · เมนูที่เลือกใช้ `.nav-item--active` (พื้นเขียวอ่อน + แถบซ้าย 2px) ไม่ใช่กล่องเขียวทึบ
- Topbar: breadcrumb ซ้าย (13px, muted, หน้าปัจจุบันเป็น 500) · โปรไฟล์ขวา
- Content padding 32px · ระยะระหว่างกลุ่ม 24–32px
- ตารางอยู่ใน `.card` · เส้นคั่นแนวนอนเท่านั้น ไม่มีเส้นตั้ง · แถวสูง 64px · hover เป็น `--bg-subtle`

## ไฟล์
- `tokens.css` — ตัวแปรทั้งหมด (import ก่อนทุกไฟล์)
- `base.css` — reset + text utilities + primitives (.btn .badge .table .nav-item .input .card .panel)
- `Typography Standard.dc.html` — เอกสารอ้างอิงภาพ เปิดในเบราว์เซอร์ได้เลย

## Checklist ก่อนส่งงาน
- [ ] ค้นหา `font-weight: 700`, `bold`, `#000`, `#111`, `#222` ในไฟล์ที่แก้ — ต้องไม่เจอ
- [ ] ค้นหาค่าสี hex ที่ไม่ได้มาจาก tokens — ต้องไม่เจอ
- [ ] ทุก `font-size` มาจากตัวแปรของ type scale
- [ ] ตารางมีคอลัมน์ที่เน้นไม่เกินหนึ่งคอลัมน์
- [ ] ทุก interactive element มี hover และ focus-visible

## มาตรฐานฟอร์ม
ระบบมีฟอร์ม **2 แบบเท่านั้น** — เลือกแบบตามปริมาณข้อมูล ไม่ใช่ตามความชอบ

| | Popup (`.modal`) | หน้าจอเต็ม (`.form-page`) |
|---|---|---|
| ใช้เมื่อ | ฟิลด์ไม่เกิน 12 ช่อง · ทำจบในที่เดียว · ไม่ต้องดูข้อมูลอื่นประกอบ | มากกว่า 12 ช่อง · มีหลายกลุ่ม · แนบไฟล์ · มีตารางย่อย |
| ขนาด | max-width 960px · max-height 80vh · เนื้อหาเลื่อนได้ | เนื้อหา max-width 1040px · จัดกลุ่มเป็นการ์ด |
| หัว | ชื่อ 20px/600 + บรรทัด "ช่องที่มี * จำเป็นต้องกรอก" + ปุ่ม ✕ | breadcrumb + ปุ่มย้อนกลับ + ชื่อ 26–28px/600 |
| ปุ่ม | แถบล่างมีเส้นคั่น พื้น #FCFDFC ชิดขวา | แถบล่างติดขอบหน้า ซ้ายเป็นตัวนับความคืบหน้า ขวาเป็นปุ่ม |

**กฎร่วมของทั้งสองแบบ**
1. Label อยู่**เหนือ**ฟิลด์เสมอ 13px/500/`--text-primary` · ระยะ label→field 8px · ห้ามวาง label ด้านซ้าย
2. ดอกจันบังคับกรอกสี `#DC2626` ตามหลัง label และต้องมีบรรทัดอธิบายที่หัวฟอร์มหนึ่งครั้ง
3. ฟิลด์: สูง 42px · padding 10px 12px · radius `--r-md` · border `--border-default` · ข้อความ 14px/400 · placeholder `--text-muted`
4. Focus: border `--brand-500` + `--focus-ring` — ห้าม outline default ของเบราว์เซอร์
5. Error: border `#FECACA` + ข้อความ 12px `--status-danger-text` ใต้ฟิลด์ 6px · submit แล้วต้อง focus ฟิลด์แรกที่ผิด
6. Grid 3 คอลัมน์ gap 20px/16px · ฟิลด์ยาว (ชื่อ, ลิงก์, ที่อยู่) ใช้ `grid-column: span 2`
7. ปุ่มอยู่ชิดขวาล่างเสมอ · "ยกเลิก" = `.btn` · "บันทึก" = `.btn--primary` ปุ่มเดียว · ขณะบันทึกให้ disable ทั้งคู่
8. ปิด popup ได้ด้วย ✕ / Esc / คลิกฉากหลัง — ถ้ามีการแก้ไขค้างต้องถามยืนยันก่อนปิด
9. **ห้ามเปลี่ยนแบบของหน้าจอที่มีอยู่** — เมนูไหนเป็น Popup ให้คงเป็น Popup เมนูไหนเป็นหน้าจอเต็มให้คงเป็นหน้าจอเต็ม เปลี่ยนเฉพาะสไตล์ให้ตรงมาตรฐาน
10. ฉากหลัง popup: `rgba(17,24,39,0.45)` ไม่ใช้สีดำทึบ · เงา popup `0 8px 12px rgba(16,24,40,.06), 0 24px 60px rgba(16,24,40,.14)`

## มาตรฐานเมนู
ทุกรายการเมนูต้องมีไอคอนเส้น 1.5px นำหน้า ขนาด 19px (เมนูย่อย 17px) gap 12px
สีไอคอนปกติ `--text-muted` · เมนูที่เลือก `--brand-600` · เมนูที่มีเมนูย่อยมี caret ขวาสี `--border-default`

## มาตรฐาน Motion และการโหลด (ต้องไม่กระพริบ)
เป้าหมาย: คลิกแล้วรู้สึกลื่นและแน่นหนา — ไม่มีจอขาวแวบ ไม่มีเลย์เอาต์กระโดด ไม่มี spinner กลางจอ

1. **ห้าม unmount เนื้อหาเดิมตอนโหลดข้อมูลใหม่** — ใส่ `.is-refreshing` (จาง 55% + กดไม่ได้) แล้วค่อยสลับข้อมูล
   การ `return <Spinner/>` แทนตารางทั้งอันคือสาเหตุอันดับหนึ่งของอาการกระพริบ
2. **โหลดครั้งแรกใช้ skeleton ไม่ใช้ spinner** — skeleton ต้องมีจำนวนแถวและความกว้างใกล้เคียงข้อมูลจริง
   spinner ใช้ได้เฉพาะในปุ่มที่กำลังบันทึก
3. **จองพื้นที่ล่วงหน้า** — ตารางใส่ `min-height`, รูปภาพกำหนด `width/height` หรือ `aspect-ratio`, badge/ตัวเลขที่เปลี่ยนค่าใส่ `min-width` + `tabular-nums`
4. **ปุ่มที่กดแล้วรออะไร ต้องเข้าสถานะ pending ทันที** — disable + เปลี่ยนข้อความ ("บันทึก" → "กำลังบันทึก…") ห้ามให้กดซ้ำได้
5. **งานที่แน่ใจว่าสำเร็จให้ optimistic update** — เช่น toggle สถานะ, ลบแถว: อัปเดต UI ทันที ถ้า API พลาดให้ย้อนกลับ + toast แจ้ง
6. **ระยะเวลา**: hover/สี 120ms · เปิด popover/dropdown 220ms · popup 260ms · ห้ามเกิน 300ms กับ UI ที่ใช้งานประจำ
7. **ทิศทาง**: สิ่งที่ปรากฏขึ้นใช้ `--ease-out` และขยับ 6px เข้าหาตำแหน่ง (ไม่ใช่ 20px) · สิ่งที่หายไปเร็วกว่าตอนเข้า
8. **เปลี่ยนหน้า/แท็บ** — เก็บ scroll position, คงหัวตารางและ filter ไว้, เปลี่ยนเฉพาะส่วนที่ต่างจริง ห้าม reload ทั้งหน้า
9. **transition เฉพาะ property ที่ถูก** — เฉพาะ `opacity`, `transform`, สี และ `box-shadow` · ห้าม `transition: all` · ห้าม animate `width/height/top/left` (ใช้ transform)
10. **เคารพ `prefers-reduced-motion`** — base.css จัดการให้แล้ว ห้ามเขียน animation ที่ข้ามกฎนี้
11. **ปุ่มกดแล้วยุบ `scale(.985)`** ทุกปุ่ม — เป็น feedback ที่ทำให้รู้สึก "กดติด"
12. **ห้าม `transition` บนสิ่งที่เพิ่ง mount** ที่ทำให้กระพริบ — ใช้ `animation … both` แทน
