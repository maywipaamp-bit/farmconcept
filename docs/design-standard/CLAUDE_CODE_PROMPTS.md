# คำสั่งสำหรับ Claude Code

รวมคำสั่งที่ก็อปวางใช้ได้เลย เรียงตามลำดับที่ควรทำ
วางไฟล์ `tokens.css`, `base.css`, `STANDARD.md` และ `Typography Standard.dc.html` ไว้ใน repo ก่อนเริ่ม

---

## 0. ติดตั้งมาตรฐาน (ทำครั้งเดียว)

```
อ่าน STANDARD.md, tokens.css และ base.css ในโฟลเดอร์นี้ แล้ว:
1. ย้าย tokens.css กับ base.css ไปไว้ที่ที่เหมาะกับโครงสร้าง repo นี้ (เช่น src/styles/)
2. import ทั้งสองไฟล์ที่ entry point ของแอป โดย tokens.css มาก่อน base.css
   และมาก่อน stylesheet อื่นทั้งหมด
3. คัดลอกเนื้อหา STANDARD.md ไปต่อท้าย CLAUDE.md ที่ root ของ repo
   (ถ้ายังไม่มี ให้สร้าง) เพื่อให้กฎนี้ถูกใช้ทุกครั้งที่แก้ UI
4. ถ้า repo ใช้ Tailwind ให้ map tokens เข้า theme ใน tailwind config
   แทนการเขียน utility class ซ้ำ
อย่าแก้ component ใด ๆ ในขั้นนี้ ทำแค่ติดตั้งและรายงานสิ่งที่ทำ
```

## 1. ตรวจสอบว่าตอนนี้ผิดกฎที่ไหน (อ่านอย่างเดียว ไม่แก้)

```
อ่าน STANDARD.md แล้วสแกน UI ทั้งหมดใน repo นี้ ทำรายงานเป็นตารางว่า
มีจุดไหนผิดกฎ พร้อมชื่อไฟล์และเลขบรรทัด แยกเป็นหมวด:
- font-weight 600/700 หรือ bold ที่ไม่ใช่หัวข้อ
- สีข้อความที่เข้มกว่า #111827 หรือ hardcode ไม่ผ่าน token
- line-height ต่ำกว่า 1.6 ในข้อความเนื้อหา
- font-size ต่ำกว่า 12px
- padding/margin ที่ไม่อยู่ในสเกล 4px
- หน้าจอที่มีปุ่มสีเขียวหลักมากกว่าหนึ่งปุ่ม
เรียงลำดับตามผลกระทบต่อภาพรวม อย่าแก้โค้ดในขั้นนี้
```

## 2. แก้ทีละหน้า (ทำซ้ำต่อหน้าจอ)

```
ทำตาม STANDARD.md ปรับหน้า <ชื่อไฟล์/route> ให้เข้ามาตรฐาน:
- แทนค่าสี ขนาด ระยะห่าง ทั้งหมดด้วยตัวแปรจาก tokens.css
- ลด font-weight ทุกจุดที่ไม่ใช่หัวข้อลงเป็น 400 และใช้ 500 เฉพาะข้อมูลหลัก
- หัวตารางเป็น 13px/500/--text-secondary
- ตารางใช้เส้นคั่นแนวนอนเท่านั้น แถวสูง 64px และมี hover
- เหลือปุ่ม .btn--primary หนึ่งปุ่ม ปุ่มอื่นเป็น .btn ธรรมดา
ห้ามเปลี่ยนโครงสร้างข้อมูล ชื่อคอลัมน์ หรือ logic ใด ๆ
เปลี่ยนเฉพาะการนำเสนอ แล้วสรุปรายการที่แก้ให้ดู
```

## 3. สร้าง component กลาง

```
ทำตาม base.css สร้าง component ที่ใช้ซ้ำได้ตามแพตเทิร์นของ repo นี้:
Button (primary/secondary/ghost + disabled), Badge (success/warning/danger/neutral),
DataTable (header, row hover, cell types: text/strong/index/number/badge/actions),
SidebarNavItem (default/active/child), Input + Field (label, help, error)
ทุกตัวต้องใช้ตัวแปรจาก tokens.css ไม่มีค่า hardcode
มี hover, focus-visible, disabled ครบทุกตัว
เขียนหน้า preview รวมทุก state ให้ตรวจสอบได้ในหน้าเดียว
```

พร้อมเพิ่มคำอธิบายวิธี override เมื่อจำเป็นจริง ๆ

## 6. ใช้มาตรฐานนี้เป็นหลัก (คำสั่งหลัก — รันก่อนคำสั่งแก้หน้าจอทุกครั้ง)

```
STANDARD.md, tokens.css และ base.css ในโปรเจกต์นี้คือมาตรฐานเดียวของ UI
ต่อจากนี้ทุกครั้งที่สร้างหรือแก้หน้าจอ ให้ยึดสามไฟล์นี้เป็นหลัก
เหนือกว่าสไตล์เดิมของ repo และเหนือกว่าค่า default ของไลบรารีที่ใช้อยู่

ข้อบังคับ:
- ห้าม hardcode สี ขนาดฟอนต์ ระยะห่าง radius เงา — ใช้ตัวแปรจาก tokens.css เท่านั้น
- ห้าม font-weight 700 · ห้ามสีข้อความเข้มกว่า #111827
- ฟอร์มต้องใช้แพตเทิร์นใน STANDARD.md หัวข้อ "มาตรฐานฟอร์ม"
- เมนูทุกรายการต้องมีไอคอนเส้น 1.5px ตามหัวข้อ "มาตรฐานเมนู"
- ถ้าเจอกรณีที่มาตรฐานไม่ครอบคลุม ให้ถามก่อน อย่าตัดสินใจเองแล้วสร้างสไตล์ใหม่

ยืนยันว่าเข้าใจ แล้วสรุปกฎที่จะใช้เป็นรายการสั้น ๆ ก่อนเริ่มแก้โค้ดใด ๆ
```

## 7. แก้ไขหน้าจอทั้งระบบ โดยคงรูปแบบเดิมของแต่ละหน้า

```
ยึด STANDARD.md เป็นหลัก ปรับหน้าจอทั้งระบบให้เข้ามาตรฐานใหม่

กฎเหล็ก — ห้ามเปลี่ยนรูปแบบของหน้าจอที่มีอยู่:
- เมนู/ปุ่มไหนที่ปัจจุบันเปิดฟอร์มเป็น Popup ให้คงเป็น Popup
  แล้วปรับสไตล์ตามมาตรฐาน Popup (.modal, .modal__head, .modal__body, .modal__foot)
- เมนู/ปุ่มไหนที่ปัจจุบันเป็นหน้าจอเต็ม ให้คงเป็นหน้าจอเต็ม
  แล้วปรับตามมาตรฐาน .form-page (breadcrumb + ปุ่มย้อนกลับ + การ์ดแยกกลุ่ม + แถบปุ่มล่าง)
- ห้ามย้าย route ห้ามเปลี่ยน URL ห้ามรวมหรือแยกหน้า
- ยกเว้นกรณีเดียว: ถ้า Popup ไหนมีฟิลด์เกิน 12 ช่องหรือมีตารางย่อย
  อย่าเปลี่ยนเอง แต่ให้ list ไว้ท้ายรายงานว่าควรพิจารณาเปลี่ยนเป็นหน้าจอเต็ม พร้อมเหตุผล

ขั้นตอน:
1. ทำ inventory ของทุกหน้าจอและทุกฟอร์มในระบบก่อน ระบุว่าแต่ละอันเป็น Popup หรือหน้าจอเต็ม
   และนับจำนวนฟิลด์ แล้วแสดงตารางให้ดูก่อนแก้
2. แก้ทีละหน้า เริ่มจากหน้าที่ใช้บ่อยที่สุด: list view → ฟอร์ม → หน้ารายละเอียด
3. ทุกหน้าที่แก้เสร็จ ให้สรุปว่าเปลี่ยนอะไร และยืนยันว่ารูปแบบ (Popup / หน้าจอเต็ม) ยังเหมือนเดิม

ห้ามแตะ logic การ validate การเรียก API ชื่อฟิลด์ หรือโครงสร้างข้อมูล
เปลี่ยนเฉพาะชั้นการนำเสนอเท่านั้น
```

## 8. ปรับฟอร์มเดิมทีละตัว (ใช้กับฟอร์มที่ซับซ้อน)

```
ยึด STANDARD.md หัวข้อ "มาตรฐานฟอร์ม" ปรับฟอร์ม <ชื่อไฟล์/ชื่อฟอร์ม> ให้ตรงมาตรฐาน
โดยคงรูปแบบเดิม (Popup หรือหน้าจอเต็ม) ไว้อย่างเดิม:
- label ย้ายขึ้นเหนือฟิลด์ทุกช่อง 13px/500 ระยะ 8px
- ดอกจันบังคับกรอกสี #DC2626 + บรรทัด "ช่องที่มี * จำเป็นต้องกรอก" ที่หัวฟอร์ม
- ฟิลด์สูง 42px radius 10px border --border-default · focus เป็น ring เขียว
- error: border #FECACA + ข้อความ 12px #B91C1C ใต้ฟิลด์ และ focus ฟิลด์แรกที่ผิดเมื่อ submit
- grid 3 คอลัมน์ ฟิลด์ยาวใช้ .span-2
- ปุ่มชิดขวาล่าง "ยกเลิก" + "บันทึก" (primary หนึ่งปุ่ม) และ disable ทั้งคู่ขณะบันทึก
- Popup: ปิดได้ด้วย ✕ / Esc / คลิกฉากหลัง และถามยืนยันถ้ามีการแก้ไขค้าง
อย่าเพิ่มหรือลบฟิลด์ อย่าเปลี่ยนลำดับฟิลด์ที่ผู้ใช้คุ้นอยู่แล้ว

## 9. ใส่ไอคอนให้เมนู

```
ยึด STANDARD.md หัวข้อ "มาตรฐานเมนู" ใส่ไอคอนให้ทุกรายการเมนูใน sidebar:
- ใช้ชุดไอคอนเส้นที่ repo มีอยู่แล้ว (Lucide / Heroicons outline) stroke 1.5px
- ขนาด 19px สำหรับเมนูหลัก 17px สำหรับเมนูย่อย gap 12px
- สีปกติ --text-muted · เมนูที่เลือก --brand-600
- เมนูที่มีเมนูย่อยมี caret ขวา และหมุน 180° เมื่อกางออก
- ไอคอนต้องสื่อความหมาย ไม่ใช้ไอคอนซ้ำกันสองเมนู
ถ้าเมนูไหนหาไอคอนที่สื่อความหมายไม่ได้ ให้เสนอตัวเลือก 2–3 แบบ อย่าเดา

## 10. ทำให้หน้าจอลื่น ไม่กระพริบ (Motion & Loading)

```
ยึด STANDARD.md หัวข้อ "มาตรฐาน Motion และการโหลด" และคลาสใน base.css
ตรวจและแก้ทั้งระบบให้คลิกแล้วรู้สึกลื่นและพรีเมียม ไม่มีอาการกระพริบ

ขั้นที่ 1 — หาสาเหตุการกระพริบก่อน (อ่านอย่างเดียว ทำรายงานพร้อมไฟล์และบรรทัด):
- จุดที่ return spinner/null แทนเนื้อหาทั้งก้อนขณะโหลด (เป็นสาเหตุอันดับหนึ่ง)
- component ที่ถูก unmount แล้ว mount ใหม่ทุกครั้งที่ข้อมูลเปลี่ยน (key เปลี่ยน, conditional render ผิดชั้น)
- รูปภาพ/ไอคอนที่ไม่กำหนดขนาด และคอนเทนเนอร์ที่ความสูงเปลี่ยนตามข้อมูล → เลย์เอาต์กระโดด
- ปุ่มที่กดแล้วไม่มี pending state จึงกดซ้ำได้
- transition: all และการ animate width/height/top/left
- การ reload ทั้งหน้า หรือ scroll เด้งขึ้นบนหลังบันทึก/เปลี่ยนหน้า

ขั้นที่ 2 — แก้ตามลำดับผลกระทบ:
1. โหลดข้อมูลใหม่: คงเนื้อหาเดิมไว้ ใส่คลาส .is-refreshing แทนการ unmount
2. โหลดครั้งแรก: ใช้ .skeleton ที่มีรูปร่างและจำนวนแถวใกล้เคียงข้อมูลจริง เลิกใช้ spinner กลางจอ
3. จองพื้นที่: min-height ให้ตาราง, aspect-ratio ให้รูป, min-width + tabular-nums ให้ตัวเลขที่เปลี่ยนค่า
4. ทุกปุ่มที่เรียก API: disable + เปลี่ยนข้อความเป็น "กำลังบันทึก…" ทันทีที่กด
5. toggle สถานะและการลบ: ทำ optimistic update + rollback + toast เมื่อพลาด
6. popup/popover/dropdown: ใช้ animation จาก base.css (om-pop-in / om-slide-in) ตอนเข้าและออก
   ต้องมี exit animation ด้วย ไม่ใช่หายวับ
7. เปลี่ยนหน้าและแท็บ: คง scroll position, filter และ pagination ไว้ อัปเดตเฉพาะส่วนที่ต่าง
8. ไล่ลบ transition: all ทั้งหมด เปลี่ยนเป็นระบุ property ตามมาตรฐาน

ขั้นที่ 3 — ตรวจซ้ำ:
วัดว่าไม่มี layout shift ตอนโหลด (ดู CLS ถ้ามีเครื่องมือ)
และยืนยันว่าทุก interaction มี feedback ภายใน 100ms

ห้ามเพิ่ม animation library ใหม่ถ้า repo ยังไม่มี
ห้ามใส่ animation ที่นานเกิน 300ms กับ UI ที่ใช้งานประจำ
ห้ามแตะ logic ธุรกิจ — เปลี่ยนเฉพาะการนำเสนอและสถานะการโหลด
```
